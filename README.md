# AI Music Teacher

Демо ИИ-учителя для тех, кто учится играть на фортепиано. Загружаете запись игры (аудио или видео), а система находит ошибки по нотам и ритму, показывает, в каком такте они произошли, и какую клавишу нужно было нажать.

> Это тестовое задание. Подход и архитектура описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), там же ответы на три вопроса из задания.

## Что умеет демо

1. **Транскрибирует** запись в ноты ([Basic Pitch](https://github.com/spotify/basic-pitch), работает локально, без платных сервисов).
2. **Сравнивает** исполнение с эталоном из MusicXML / MIDI: выравнивание нот и подбор карты времени, чтобы другой темп не считался ошибкой.
3. **Находит ошибки пяти типов:** не та нота, пропуск, лишняя нота, позже, раньше. Для каждой указывает такт и долю.
4. **Показывает итоговый разбор:** общую точность, точность по высоте и ритму, проблемные такты, нотный график с ошибками и клавиатуру с нужной и нажатой клавишей.
5. **Даёт рекомендации и план занятия:** объяснение каждой ошибки, советы и пошаговый план повторения проблемных тактов (правила и шаблоны, без платных моделей).

В комплекте произведение «Ода к радости» (8 тактов) и две демо-записи: чистая и с четырьмя заложенными ошибками (`demo/`), поэтому всё можно проверить, не имея своей записи.

## Быстрый старт

Нужно: **Node.js 22+**, **Python 3.11** и **ffmpeg** в `PATH`.

```bash
npm install
npm run setup   # .env, база данных и Python-окружение для транскрипции
npm run dev     # фронтенд, API и транскрибер вместе
```

Откройте <http://localhost:5173> и нажмите **«Демо: исполнение с ошибками»**.

| Сервис | Адрес |
| --- | --- |
| Web (Vite) | http://localhost:5173 |
| API (NestJS) | http://localhost:3000/api |
| Transcriber (FastAPI) | http://127.0.0.1:8001 |

Транскрибер несколько секунд загружает модель при старте, поэтому первые запросы могут вернуть 503, пока он не готов. Сам анализ короткой записи занимает несколько секунд.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run setup` | Создаёт `backend/.env`, применяет миграции, ставит Python-зависимости |

## Структура

```
frontend/           React + Vite + shadcn/ui + TanStack Query
  src/app/            роутер, провайдеры, layout
  src/features/       attempts/ (страницы, компоненты, API-хуки), scores/
  src/lib/            API-клиент, типы, названия нот
backend/            NestJS + Prisma (SQLite)
  src/scores/         парсеры MusicXML / MIDI, эталоны
  src/transcription/  клиент Python-сайдкара
  src/analysis/       выравнивание, карта темпа, классификация ошибок
  src/feedback/       рекомендации и план занятий (FeedbackGenerator)
  src/attempts/       оркестрация: запись → ноты → разбор → хранение
  src/demo/           раздача демо-записей
transcriber/        Python (FastAPI): ffmpeg + Basic Pitch на ONNX Runtime
demo/               демо-записи, их транскрипции и ground-truth.json
docs/               ARCHITECTURE.md
```

Логика анализа это чистые функции без зависимостей от Nest, БД и Python, поэтому она тестируется напрямую. Подробности в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## API

| Метод | Путь | Описание |
| --- | --- | --- |
| `GET` | `/api/scores`, `/api/scores/:id` | Произведения и их ноты |
| `POST` | `/api/scores` | Загрузить эталон (`.musicxml` или `.mid`, поле `file`) |
| `POST` | `/api/transcriptions` | Аудио или видео → ноты (поле `file`) |
| `POST` | `/api/attempts` | Новая попытка: поля `file` и `scoreId`, отвечает готовым разбором |
| `GET` | `/api/attempts`, `/api/attempts/:id` | История и разбор |
| `GET` | `/api/attempts/:id/audio` | Сохранённая запись |
| `GET` | `/api/demo`, `/api/demo/:name` | Демо-записи |

Попробовать без интерфейса:

```bash
curl -F "scoreId=<id из GET /api/scores>" -F "file=@demo/ode-to-joy-mistakes.wav" http://localhost:3000/api/attempts
```

## Объём работы и допущения

Задание не оплачивается, поэтому объём сознательно ограничен: одно произведение-эталон, одноголосная мелодия, без авторизации и очередей задач, только бесплатные open-source компоненты. Из возможностей вакансии реализован главный сценарий: **анализ исполнения → сравнение с эталоном → отчёт**. Остальное (OMR, голосовой диалог, live-комнаты) описано в [архитектуре](docs/ARCHITECTURE.md) без реализации.

Известные ограничения:

- Пороги проверены на синтетических записях. Живая запись с педалью и шумом даст больше ложных срабатываний.
- Эталон считается с постоянным темпом.
- Запись с микрофона в браузере не реализована: только загрузка файла.
- Весь интерфейс на русском.
